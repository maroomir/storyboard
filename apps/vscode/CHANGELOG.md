# 변경 내역

Storyboard의 주요 변경 사항을 한국어로 기록합니다.

이 문서는 [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) 형식을 따르며,
첫 공개 릴리스 이후에는 [Semantic Versioning](https://semver.org/spec/v2.0.0.html)을 따릅니다.

영어 변경 내역은 [CHANGELOG.en.md](CHANGELOG.en.md)를 참고하세요.

## [0.9.1] - 2026-09-11

### 고침

- **시점 교차 구성이 작품 시점과 어긋난 서술자 카드를 만들던 문제를 고쳤습니다.** 프리셋이 시점에서 인칭·지식 경계를 따로 계산해, 2인칭 작품에는 3인칭 서술자 카드가, 전지적 시점 작품에는 목격 범위 서술자 카드가 만들어졌습니다. 이제 형식이 정의한 파생 규칙 하나만 씁니다.
- **`storyboard config set` 이 `timeoutMs`·`reasoningEffort` 를 거부하던 문제를 고쳤습니다.** 받을 수 있는 칸의 목록과 실제 검사가 따로 적혀 있어 두 칸이 검사에서 빠져 있었습니다.
- **설정 화면에 보이는 기본값·허용 범위와 실제 생성에 쓰이는 값이 갈라질 수 있던 문제를 고쳤습니다.** 설정 하나의 기본값과 범위가 세 곳에 따로 적혀 있어, 한쪽만 고치면 조용히 어긋났습니다.

### 변경

- **제공자 이름 표기가 한 곳에서 나옵니다.** 여덟 제공자가 «키 없음·모델 없음·연결 실패·생성 실패» 문장을 각자 적고 있어서, xAI·Claude Code 등 일부 제공자의 이름이 화면마다 달랐습니다. 이제 모두 카탈로그의 표시명을 씁니다.

### 내부

- 흩어져 있던 값에 소유자를 하나씩 정했습니다. 제공자 표(모델·요금·기본 명령), 비평 카테고리, 경로·확장자·감시 글롭, CLI 도움말과 자동완성 목록, 확장 기여 id, 반복되는 안내 문구가 각각 한 표에서 나옵니다. 프롬프트 35개의 temperature·토큰 예산과 생성 파이프라인 기본값은 `*.params.json` 파일로 모아 실측으로 조정할 자리를 한곳에 두었습니다.
- 소유자가 정해진 문자열이 다른 파일에 다시 나타나면 아키텍처 검사가 빌드를 실패시킵니다. 규칙을 적어 두는 것만으로는 다음 사람이 리터럴을 다시 적는 것을 막지 못하기 때문입니다.

## [0.9.0] - 2026-09-10

### 제거

- **Telegram 봇(`storyboard-bot`)이 사라졌습니다.** 텔레그램에서 워크스페이스를 조회·편집·생성하던 앱을 저장소에서 걷어냈습니다. 봇만을 위해 존재하던 «저장 = 커밋» 쓰기 모델(mutate gate·신선도 가드)과 커밋·동기화 패키지(`@storyboard/story-git`), 잡 큐와 네이티브 의존(`better-sqlite3`)도 함께 사라집니다. 남는 것은 VSCode 확장과 CLI 둘이고, 릴리즈 산출물도 VSIX 와 CLI tarball 둘입니다. 폰에서 초안을 읽는 방법은 워크스페이스를 git 클라이언트로 클론하는 것이며, 이제 그 저장소는 `storyboard init` 이 만들어 줍니다.

### 추가

- **`storyboard init` 이 git 저장소도 만듭니다.** 지금까지 워크스페이스를 저장소로 만들어 주는 것은 봇의 `/doctor init` 뿐이어서, 확장이나 CLI 로 시작한 작품은 사용자가 직접 `git init` 을 해야 했습니다. 이제 `init` 과 `init --repair` 가 `.gitignore` 를 먼저 쓴 뒤 저장소가 아니면 `git init` 을 실행하므로, 생성물이 첫 커밋에 쓸려 들어갈 여지 없이 작품이 처음부터 이력 위에서 시작합니다. 첫 커밋은 여전히 사용자의 몫이고, `storyboard doctor` 가 저장소가 아닌 워크스페이스를 짚어 줍니다.

## [0.8.10] - 2026-09-10

### 추가

- **이야기 상태 원장을 다시 봉인할 수 있습니다.** 카드를 고쳤지만 지금 초안이 맞다고 판단했을 때, `storyboard state reseal [<씬 범위>]` 와 익스텐션의 **Storyboard: Reseal Story State** 가 그 판단을 원장에 남깁니다. 지금까지는 낡음 표시를 지우는 길이 초안 재생성뿐이어서, 비트만 채워 넣어도 그 씬이 남긴 사실이 통째로 프롬프트에서 빠졌습니다. 봉인은 되돌릴 수 없으므로 익스텐션에서는 대상 씬을 보여 주고 확인을 받습니다.
- **`doctor` 가 모델과 씬 목표 분량이 맞는지 봅니다.** 씬 목표가 큰 작품에서 실측상 목표를 못 채우는 모델을 쓰고 있으면 그 사실과 실측 달성률을 알려 줍니다. 생성에 수십 분을 쓴 뒤에야 분량 미달을 발견하는 일을 줄입니다. 재보지 않은 프로바이더·모델 조합에 대해서는 아무 말도 하지 않습니다.

### 변경

- **모델마다 실측으로 정한 생성 파라미터를 씁니다.** 씬을 몇 구간으로 나눠 쓸지 같은 값이 모델마다 다르게 최적입니다. Opus 는 목표 15,000자 씬을 **한 번에** 쓸 때 가장 좋아(목표의 101%, 호출 1회) 구간 상한이 15,000으로 잡힙니다 — 종전 3회 호출로 92%였던 것보다 분량은 늘고 비용은 1/3입니다. 뼈대에 배분하는 비율도 모델마다 반대로 최적입니다: Sonnet 은 0.8로 올려야 목표의 44%→61%로 오르고, Opus 는 같은 값에서 137%까지 넘쳐 종전 1/3이 맞습니다. 재보지 않은 모델은 종전 기본값 그대로이고, `config show` 가 그 값의 출처를 «모델 실측»으로 구분해 보여 줍니다. 사용자가 지정한 값은 언제나 우선합니다.
- **`claude-code` 의 기본 모델이 Opus 로 바뀌었습니다.** 실측에서 씬 목표 15,000자 작품의 초안이 Sonnet 은 목표의 47%, Opus 는 92%였습니다. 기본값이 목표를 못 맞추면 원인을 파이프라인에서 찾게 되므로 기본을 Opus 로 두었습니다. 비용을 아끼려면 `storyboard config set providers.claude-code.model sonnet` 또는 설정 패널에서 되돌릴 수 있습니다.
- **설정을 git 처럼 저장합니다.** `storyboard config set` 과 `storyboard setup` 은 워크스페이스 안에서 실행하면 그 작품의 `.storyboard/config.json` 에 쓰고, 모든 작품에 걸려면 `--global` 을 붙입니다. 워크스페이스 밖에서 플래그 없이 부르면 어디에 쓸지 모호하므로 거부합니다. 예전에는 언제나 공용 파일에 써서 작품별 설정을 두려면 파일을 손으로 만들어야 했습니다. API 키는 종전대로 0600 홈 파일 하나에만 저장됩니다.

### 고침

- **비트를 채운 씬의 초안이 오히려 짧아지던 문제.** 씬 카드에 비트가 있으면 뼈대 단계가 카드의 목적·갈등·반전·감정 변화 블록을 통째로 받지 못했습니다. 사건 재료만 남기려던 필터가 설계 블록까지 함께 버렸기 때문입니다. 이제 설계 블록은 «장면 설계»로 따로 전달되어 사건 재료와 섞이지 않으면서도 뼈대에 도달합니다. 실측(sonnet, 목표 3,000자)에서 뼈대가 743자 → 1,900자, 초안이 1,636자 → 2,928자(목표의 98%)로 늘고, 비트가 있을 때와 없을 때의 분량 차이가 37%에서 0.4%로 사라졌습니다. 사건 커버리지는 그대로였습니다.
- **`doctor` 가 존재하지 않는 명령을 안내하던 문제.** 이야기 상태가 낡았을 때 `storyboard draft generate` 를 실행하라고 알려 줬지만 그런 명령이 없어 그대로 치면 실패했습니다. 실제 해소 명령인 `storyboard scene generate --all` 로 고쳤습니다.

## [0.8.9] - 2026-09-07

### 추가

- **`storyboard-bot` 에 터미널 명령이 생겼습니다.** `storyboard-bot doctor` 가 설정 파일·워크스페이스·git·프로바이더를 점검하고, `--help`·`--version` 이 사용법과 버전을 알려 줍니다. 텔레그램의 `/doctor` 와 달리 봇이 뜨지 않는 상태에서도 답하므로, 설정이 없거나 깨졌을 때 원인을 터미널에서 바로 볼 수 있습니다.
- **캐넌의 유효 구간을 이야기 시간으로 잽니다.** 씬 카드에 정수 `storyTime`을 적으면 유효 구간을 그 축으로 재므로, 회상·액자·시간 점프가 있어도 «20화에서 죽은 인물이 25화 회상에서도 죽어 있는» 일이 없습니다. 적지 않은 씬은 종전대로 씬 순번을 쓰고, 시간축을 쓰는 사실이 하나도 없으면 씬을 읽지도 않습니다. 공개 시점(`revealFrom`)은 독자가 읽은 순서의 문제라 씬 순번으로 남겼고, `{ scene, knownBy }` 형태로 «A는 알고 B는 모르는» 상태를 쓸 수 있습니다 — 모르는 인물은 `(아직 모름: 지훈)`으로 표시되어 극적 아이러니가 유지됩니다.
- **살붙임 구간 상한을 설정할 수 있습니다.** `draft.sectionOutputLimit`(기본 7,000)을 낮추면 구간이 잘게 나뉘어 호출이 늘고 분량이 늘어납니다. 목표가 상한보다 작으면 살붙임이 한 번뿐이라 분량이 뼈대 수준에 갇히는데, 프롬프트의 글자 수 지시가 실측에서 듣지 않아 손댈 방법이 없었습니다.

### 변경

- **인식하지 못하는 인자를 거부합니다.** 예전에는 `storyboard-bot init` 처럼 잘못 친 명령이 조용히 무시되고 봇이 그대로 떴기 때문에, 오타인지 설정 문제인지 구분되지 않았습니다. 이제 사용법과 함께 종료 코드 1로 끝납니다.
- **설정이 없을 때의 메시지가 온보딩 안내로 바뀌었습니다.** 첫 실행은 오류가 아니므로 `storyboard-bot setup` 을 안내합니다. 설정 파일이 있는데 깨진 경우는 종전처럼 ERROR 로그로 남습니다.
- **최종 검수가 장 단위로 나뉘어 돕니다.** 이전에는 전권을 한 호출에 넣어, 2~3권 분량이면 모델의 주의가 뒤로 갈수록 옅어져 한복판의 모순이 사실상 검출되지 않았습니다. 이제 장마다 연속성·비평을 한 쌍씩 부르고 앞 장의 요약을 함께 실어 장 경계를 넘는 모순도 봅니다. 긴 컨텍스트 모델에 기대지 않으므로 제공자를 바꿔도 검수 품질이 그대로입니다.

### 고침

- **사건이 적은 씬의 초안이 목표 분량에 한참 못 미치던 문제를 고쳤습니다.** 뼈대 프롬프트가 «묘사를 넣지 마라»와 «목표 N자»를 동시에 걸어 두 지시가 충돌했고, 어느 쪽을 택할지는 모델 성향에 달렸습니다. 실측에서 목표의 1/3만 쓰고 살붙임이 9배 확장을 떠안아 최종 분량이 목표 절반에도 못 미쳤습니다. 이제 분량을 묘사가 아니라 사건의 밀도로 채우도록 우선순위를 못박고, 뼈대가 목표의 절반에도 못 미치면 사유를 실어 한 번 더 부릅니다.
- **살붙임이 분량을 되풀이로 채우지 않습니다.** 재료가 바닥나면 모델이 분량을 채울 수단은 되풀이뿐이라, 앞 구간이 쪼개 쓴 대사를 다음 구간이 통째로 다시 쓰고 마무리 동작을 두 번 넣는 일이 있었습니다. 기존 검사는 구간 전체를 다시 쓴 경우만 잡아 이런 작은 되풀이는 통과했습니다. 이제 되풀이를 위반으로 잡아, 되풀이로 채운 긴 판보다 짧고 깨끗한 판이 남습니다.
- **긴 대사를 여러 문장으로 쪼개도 «대사가 사라졌다»고 오판하지 않습니다.** 조각을 하나씩 원문과 견주다 보니 쪼갠 대사가 각각 임계값에 못 미쳐 소실로 잡혔고, 재시도를 두 번 태우고 경고를 초안에 남겼습니다. 이제 이어진 조각을 합쳐서도 견줍니다.
- **앞 장을 고치면 그 장의 요약이 낡음으로 표시됩니다.** 요약이 어느 초안에서 나왔는지 기록이 없어, 앞 장을 재작성해도 요약은 옛 텍스트로 굳은 채 폐기된 판본의 줄거리가 다음 장 프롬프트로 계속 주입됐습니다. 표시된 장은 지우지 않고 프롬프트에서만 빠지며, 생성 경고와 `doctor`가 다시 요약할 장을 알려 줍니다.
- **앞 씬을 다시 쓸 때 뒤 씬의 정보가 새지 않습니다.** 인물·배경 기억이 카드 해시만 보고 재사용돼, 씬 30까지 진화한 기억이 씬 5를 다시 만드는 자리에 그대로 쓰였습니다. 이제 지금 만드는 씬보다 뒤에서 갱신된 기억은 새로 뽑습니다 — 원장에는 있던 되감기가 카드 기억에만 없던 비대칭을 맞췄습니다.

### 제거

- **CLI 가 0.8 이전의 `cli.json`·`cli-secrets.json` 을 더 이상 읽지 않습니다.** 공용 `~/.storyboard/config.json`·`secrets.json` 으로 이름을 바꾸거나 `storyboard setup` 을 다시 실행하세요.

## [0.8.8] - 2026-09-07

### 추가

- **시점을 씬·장마다 바꿀 수 있습니다.** 작품 계약의 시점이 1인칭 회고·2인칭을 포함해 다섯 값으로 늘었고, 시점에 이름을 붙인 **서술자 카드**(`narrator/*.card`)를 만들면 씬 카드의 `narrator`나 `chapters.yaml` 장의 `narrator`로 그 시점을 고를 수 있습니다. 서술자는 인칭·지식 경계(목격 범위/전지/회고)·시제·목소리를 가지며, 해석 순서는 씬 > 장 > 프로젝트입니다. 서술자 카드를 만들지 않으면 종전처럼 계약의 시점 하나가 모든 씬에 적용됩니다. 씬의 서술자·연속성 줄기·시점 인물은 초안 캐시와 원장 감사의 입력에 포함되므로, 시점만 바꿔도 초안이 다시 만들어지고 그 씬이 남긴 이야기 상태는 낡음으로 표시됩니다.
- **구성을 고르면 옴니버스·시점 교차·액자식으로 씁니다.** 작품 계약의 **구성**에서 고르면 연속성 줄기와 서술자 카드를 프리셋이 만들고, 아웃라인 생성이 그 구성에 맞는 지시(편마다 독립된 결말, 장별 서술자 배정, 외화의 앞뒤 배치)를 받습니다. 옴니버스에서는 이야기 상태 원장·장 요약·직전 씬 맥락·인물 기억이 편 안에서만 이어지고 캐넌만 공유됩니다.

- **`doctor`가 읽지 못한 원장 줄을 알려 줍니다.** 손으로 고치다 `- [2!!] …`처럼 태그가 깨지면 그 항목은 시점 필터와 낡음 판정을 받지 못한 채 조용히 남습니다. 이제 줄 수와 예시를 보고하며, 줄기별 원장까지 함께 봅니다.

- **설정과 API 키가 세 앱이 함께 쓰는 `~/.storyboard/`로 옮겨 갑니다.** 이전에는 확장은 VSCode `settings.json`과 비밀 저장소, CLI는 `cli.json`, 봇은 `bot.json`에 따로 두어 같은 키를 세 번 넣어야 했습니다. 이제 공통 설정은 `~/.storyboard/config.json`, 작품별 설정은 `<워크스페이스>/.storyboard/config.json`, 키는 `~/.storyboard/secrets.json`(0600) 한 곳입니다. **확장은 처음 켤 때 기존 `storyboard.*` 설정과 저장된 키를 자동으로 한 번 옮기고 VSCode 쪽에서 지웁니다** — 별도 작업은 필요 없지만, 이후로는 VSCode 설정 화면에 `storyboard.*` 항목이 나오지 않고 설정 패널에서 바꿉니다. CLI의 옛 `cli.json`·`cli-secrets.json`과 봇의 `bot.json` AI 블록은 경고와 함께 당분간 계속 읽힙니다.
- **AI 제공자를 고르기 전에는 생성이 거부됩니다.** 이전에는 기본값이 `mock`이라 설치 직후 아무것도 고르지 않아도 가짜 초안이 만들어졌습니다. 이제 제공자가 없으면 오류로 멈추고, 확장은 «제공자 선택» 버튼을, CLI는 `storyboard setup`을 안내합니다. 인라인 완성·문법·연속성 같은 배경 기능은 오류 없이 조용히 건너뜁니다.

### 추가

- **CLI가 대화형 화면을 갖습니다.** 인자 없이 `storyboard`를 실행하면(또는 `storyboard tui`) 워크스페이스와 제공자를 머리에 띄운 화면이 열려, 명령을 이어서 입력하고 진행과 결과를 그 자리에서 봅니다. 접두 제안(Tab)·히스토리·`/help` `/doctor` `/setup` `/clear` `/quit`를 지원하며, 터미널이 아니면 열리지 않으므로 에이전트가 갇힐 일은 없습니다.
- **셸 탭 완성이 붙습니다.** `storyboard completion <zsh|bash|fish>`가 등록 스크립트를 내며, 명령·옵션은 물론 워크스페이스의 씬·카드 이름까지 완성합니다. `install.sh`로 설치하면 쓰는 셸의 rc 파일에 자동 등록됩니다.
- **`setup`·`doctor`·`config` verb가 생겼습니다.** `setup`은 새 기기에서 제공자와 키를 잡아 주고, `doctor`는 홈·설정·제공자·키·실행 파일·워크스페이스를 점검해 **고치는 명령까지** 알려 주며, `config show|set`은 값과 그 값이 어디서 왔는지 보여 줍니다.
- **`--help`가 읽을 만해졌습니다.** 30개 명령이 7개 그룹과 예시로 정리되고, `<명령> --help`로 개별 도움말을, `-h`/`-v`도 받습니다. 오타는 가까운 명령을 제안합니다. 인자 없이 실행해도 더 이상 오류로 끝나지 않습니다.
- **오래 걸리는 8개 명령이 진행 상황을 보여 줍니다.** 씬 시드 생성과 구형 씬 변환은 N/M 진행률까지 표시합니다.
- **실패 알림에 다음 행동 버튼이 붙습니다.** API 키가 없으면 «설정 열기», 제공자가 없으면 «제공자 선택»이 토스트에 함께 뜹니다(13곳). 빈 사이드바도 안내 문장 대신 실행 버튼을 보여 줍니다.
- **설정 패널이 저장 결과와 값의 출처를 알려 줍니다.** 저장하면 «이 작품 / 공통 설정 중 어디에 저장됐는지»를 알리고, 값마다 출처 배지가 붙습니다. 새 «옵션» 탭에서 생성·검수 스위치를 바꿀 수 있고, 상태바에서 현재 기본 제공자와 모델을 볼 수 있습니다.
- **봇도 공통 설정을 읽습니다.** 확장이나 CLI에서 고른 제공자가 봇에 그대로 적용되고, `/doctor`가 실제로 쓰이는 제공자를 보고합니다.

### 고침

- **구독형 제공자의 비용 배지가 항상 $0.00으로 나오던 문제를 고쳤습니다.** `codex`·`claude-code`처럼 단가가 없는 제공자는 «12.3k 토큰»으로, 단가가 있는 제공자는 «$0.42 · 12.3k»로, 기록이 없으면 «—»로 구분해 표시합니다. Studio 대화의 사용량도 이제 장부에 잡힙니다.
