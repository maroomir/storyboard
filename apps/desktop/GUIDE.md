# Storyboard 에디터 가이드

이 문서는 `draft/*.md` 편집 중 사용하는 기능의 실제 사용 흐름을 정리합니다.

## 0) Storyboard · Studio 패널 (엔티티 대화)

- 위치: 액티비티바의 **Storyboard · Studio** 컨테이너. 항상 보이는 패널이라 본문을 끝까지 스크롤해도 입력창이 사라지지 않습니다. 편집기 우측에 두고 싶으면 뷰 헤더를 **Secondary Side Bar**(우측 패널)로 드래그하세요.
- 대상: 현재 활성 편집기를 자동으로 인식합니다. 대화할 수 있는 대상은 **인물 카드**(`character/*.card`), **배경 카드**(`background/*.card`), **씬**(`scene/*.card`와 그 초안 `draft/*.md`) 세 가지입니다. 씬 카드와 초안은 한 대상으로 묶여 **같은 대화를 공유**하되, **고칠 파일은 지금 열어 둔 쪽**입니다 — 씬 카드를 보고 있으면 씬 시드를, 초안을 보고 있으면 본문을 고칩니다. 무대 카드의 "지금 고칠 대상" 줄에 어느 파일인지 표시되고, 열지 않은 쪽은 자료로만 참고됩니다.
- 씬 카드에서 고칠 수 있는 필드: 서술 항목(`title` `summary` `purpose` `conflict` `twist` `emotionalShift` `endState` `foreshadowing` `mood` `relationStage`)과 참조 항목(`characters` `location`)입니다. 긴 설명문을 붙여넣으면 에이전트가 필드로 구조화해 한 번에 채워 줍니다. 단 `characters`·`location`에는 **실제로 존재하는 카드 id만** 들어갑니다 — 없는 카드를 가리키는 제안은 적용 단계에서 거부되고, 에이전트는 그 인물 카드를 먼저 만들라고 알려 줍니다. `grounding`·`targetWordCount`·`povCharacter`·`neededCanon`은 파이프라인이 계산하는 값이라 대화로 바꿀 수 없습니다.
- 지금 무대: 상단 카드에 대상 요약이 나옵니다. 씬이면 제목·초안 분량·버전·마지막 갱신·검수 상태와 연결된 인물·배경 카드를, 카드면 역할·등장 씬 수·관계 수와 관계 목록을 보여 줍니다(초안 버전은 `storyboard.draft.keepHistory`로 이력을 남길 때만 표시).
- 사용법: 하단 입력창에 고치고 싶은 내용을 자연어로 적어 보냅니다(예: "과거사에 화재 사건을 더해줘", "도입부를 더 긴장감 있게"). 에이전트가 대상 파일과 관련 자료를 읽고 판단해,
  - 지시가 모호하면 **되묻고**(선택지를 누르면 바로 답이 됩니다),
  - 정보만 필요하면 **답하고**,
  - 검사나 초벌 변환이 필요하다고 판단하면 **도구를 부르고**(아래 참고),
  - 고칠 내용이 정해지면 **수정 제안**을 냅니다.
    되묻기는 한 대화에서 최대 5번까지만 합니다.
- 도구: 에이전트가 스스로 판단해 대상에 맞는 도구를 씁니다("설정이랑 어긋나는 데 있는지 봐줘", "이 문단을 도구로 늘려서 다듬어줘"처럼 직접 시켜도 됩니다).
  - **`/`로 직접 지정**: 입력창에 `/`만 치면 쓸 수 있는 도구 목록이 뜹니다(`/continuity` `/grammar` `/expand` `/condense` `/augment`). 위·아래 화살표로 고르고 `Enter`나 `Tab`으로 확정하면 입력창에 **칩**으로 박히고, 뒤에 주문을 이어 적을 수 있습니다(예: `[/expand]` + "비 오는 분위기를 더 살려서"). 아무것도 적지 않고 그냥 보내도 됩니다. 칩은 `✕`나 빈 입력창에서 `Backspace`로 뗍니다. 지정하면 에이전트는 그 도구를 **반드시** 쓰되, 구간 선택과 결과 다듬기는 그대로 합니다.
  - `/`는 입력창 전체가 `/단어`일 때만 메뉴로 동작합니다. 문장 속 `draft/01.md` 같은 표기는 그냥 글자입니다.
  - **연속성 검사 / 문법 검사**: 결과를 대화로 요약해 주고, 같은 내용을 에디터에도 물결선 진단으로 표시합니다(파일을 닫으면 사라집니다).
  - **확장 / 축소 / 카드 보충**: 지목한 구간을 전용 프롬프트로 초벌 변환한 뒤, 에이전트가 대화 맥락에 맞게 다듬어 수정 제안으로 만듭니다. 결과는 언제나 제안 카드를 거치므로 승인 없이 파일이 바뀌는 일은 없습니다.
  - **카드 대화의 도구**: 인물·배경 카드에서는 `/collect`(이 카드가 등장하는 초안들에서 더할 정보 수집), `/audit`(다른 자료와 어긋나는지 검사), `/relations`(관계·참조가 실제 카드를 가리키는지, 상대 카드에도 관계가 있는지 점검)를 쓸 수 있습니다. 씬 카드에서는 `/audit`과 `/relations`(characters·location 참조 점검)를 쓸 수 있습니다. `/relations`는 파일만 확인하므로 AI 요청을 쓰지 않습니다.
  - 도구는 한 턴에 최대 2번까지만 돕니다(관계 점검을 뺀 호출마다 AI 요청이 추가됩니다).
- 카드 업데이트: `/update` 를 고르고 카드의 설명문을 붙여넣으면(이름을 앞세워서, 예: "정난정 — 조선 중기의 인물…") 인물/배경을 판별해 카드를 준비합니다 — **없는 카드면 빈 카드를 만들어 열고, 이미 있으면 그 카드를 엽니다.** 이어서 "이 설명으로 카드를 채워줘" 지시가 입력창에 채워지고, 보내면 평소의 채우기 대화(제안→diff→승인)로 이어집니다. `/update` 는 파일을 열지 않은 상태에서도 쓸 수 있습니다. 씬 카드는 순번·생성 계약과 묶여 있어 `/update` 대상이 아닙니다(씬은 Scenes 뷰에서 만든 뒤 대화로 채우세요).
- 수정 제안: 제안 카드에는 요약, 바뀌는 범위(카드 필드 N곳 / 본문 N구간), 그리고 **정합성 검사 배지**가 붙습니다. 기존 카드·씬과 충돌할 소지가 있으면 무엇이 어긋나는지 경고로 보여 주되 승인은 막지 않습니다(작가가 의도적으로 설정을 바꾸는 경우가 있으므로).
  - **diff 보기**로 적용 전 변경을 확인하고, **승인**해야 파일에 반영됩니다. **거절**하면 아무것도 쓰지 않습니다.
  - 제안을 만든 뒤 그 파일이 다른 곳(에디터 직접 편집, Telegram 봇 등)에서 바뀌었다면 적용을 거부합니다. 다시 요청하세요.
  - 초안 수정은 고칠 구간의 원문을 함께 확인합니다. 지목한 위치와 원문이 어긋나면(모델이 위치를 잘못 셌을 때) 적용하지 않고 다시 요청하라고 알립니다.
  - `storyboard.draft.keepHistory`가 켜져 있으면 초안에 적용하기 직전 이전 초안을 `.draft` 히스토리에 보관합니다.
  - 한 제안은 **대상 파일 하나만** 고칩니다. 다른 카드나 씬도 손봐야 하면 제안 카드(또는 답변) 아래에 **이어서 고칠 대상** 버튼이 나옵니다.
  - 카드의 `id`와 `type`은 대화로 바꿀 수 없습니다(파일명·참조와 연결되어 있어 rename 명령을 쓰세요).
  - 인물 카드의 `description`·`traits`·`voice`·`desire`에는 **이야기 내내 참인 상태**만 들어갑니다. "…한 뒤 흔들린다", "…을 깨닫는다" 같은 **변화 과정은 `arc`**에 단계(`stage`)·요약(`summary`)·씬 참조(`sceneRef`)로 정리됩니다. 상태 필드는 모든 씬 생성 프롬프트에 함께 읽히므로, 뒷부분 줄거리가 거기에 적히면 앞 씬이 결말을 미리 흘립니다. `arc`는 씬 생성에 주입되지 않아 안전합니다.
- 이어서 고칠 대상: 버튼을 누르면 그 파일을 preview 탭으로 열고 새 대화를 시작하면서, 넘겨받은 지시문을 입력창에 **미리 채워 둡니다**(자동으로 보내지 않으니 다듬어서 보내세요). 에이전트가 지목했더라도 실제로 없는 카드·씬은 버튼으로 나오지 않습니다.
- 넘어온 작업: 파급을 알린 제안을 **승인**하면, 지목된 대상에 "다른 곳에서 넘어온 작업"이 기록됩니다. 나중에 그 카드나 씬을 열면 무대 카드 아래에 목록으로 뜨고, 눌러서 지시문을 입력창에 채우거나 ✕로 지울 수 있습니다. 그 대상에 수정이 한 번이라도 적용되면 자동으로 사라집니다. 목록은 `.storyboard/cache/studio-followups.json`에 있습니다(gitignore 대상).
- 진행 상황: 응답을 기다리는 동안 **생각하는 중 / 관련 자료를 찾는 중 / 도구를 실행하는 중 / 정합성을 확인하는 중** 단계가 표시되고, **중단** 버튼으로 기다림을 그만둘 수 있습니다.
- 대화 기록: 대화는 워크스페이스의 `.storyboard/cache/studio-sessions/<종류>/<대상>/`에 대상별로 저장됩니다. **대화는 대상 하나에 묶여 있어, 다른 카드나 씬을 열면 대화창이 그 대상의 것으로 바뀝니다**(이전 대상의 대화는 저장된 채 남고, 새 대상의 마지막 대화가 자동으로 복원됩니다). 헤더의 **대화 기록** 아이콘으로 그 대상의 지난 대화를 골라 이어갈 수 있습니다. **새 대화** 아이콘은 새 세션을 시작합니다. 수정이 실제로 적용된 대화는 계속 보관되고, 아무것도 바꾸지 않은 대화만 대상당 10개까지 남습니다. 카드 이름을 바꾸면 대화도 함께 따라갑니다.
- 정합성 검사는 제안마다 AI를 한 번 더 부릅니다. 요청 수를 아끼려면 `storyboard.studio.validation` 설정을 끄세요(제안 배지가 "정합성 검사 안 함"으로 바뀝니다).
- 초안 생성·재생성, 이야기 완결, 씬 기반 카드 구성 같은 파이프라인 작업은 Studio 대화가 아니라 명령 팔레트와 뷰 헤더 버튼에서 실행합니다. 문법·연속성 검사는 명령 팔레트로도, 초안 대화의 도구로도 돌릴 수 있습니다.

## 1) 인라인 완성

- 대상: `draft/*.md`
- 동작: 커서 앞 문맥을 기준으로 Ghost Text 제안을 표시합니다.
- 수락: 기본 VS Code 인라인 제안 수락 키(일반적으로 `Tab`)를 사용합니다.
- 주의: 디바운스(약 700ms)와 메모리 캐시가 적용되어 즉시 반복 호출되지 않을 수 있습니다.

## 2) 문법 검사 + Quick Fix

- 실행 방법
  - 저장 시 자동 검사
  - 명령: `Storyboard: Grammar Check (Draft)`
- 결과: 경고 진단(`squiggle`)이 표시됩니다.
- 수정: 문제 구간에서 Quick Fix를 실행하면 제안 교정문을 적용할 수 있습니다.
- 실시간 검사: `storyboard.grammar.realtimeEnabled`가 `true`일 때만 입력 중 검사합니다.

## 3) 연속성 검사

- 대상: `draft/*.md` (프로젝트에 `.storyboard/bible/canon.yaml` 정전 설정이 있을 때)
- 실행 방법
  - 명령: `Storyboard: Continuity Check (Draft)`
- 동작: 초안 본문을 등장 인물/배경의 정전(canon) 설정과 대조해 모순되는 구간을 경고 진단으로 표시합니다.
- 주의: 해당 씬에 적용되는 canon 사실이 없으면 모델을 호출하지 않고 건너뜁니다.
- canon 채우기: 초안을 생성하면 설정 사실 후보가 자동 추출됩니다. `Storyboard: Promote Bible Candidates to Canon` 명령으로 후보를 골라 canon으로 승격하면 주입·검사 대상이 됩니다.

## 4) 선택 영역 확장

- 명령: `Storyboard: Expand Selection (Draft)`
- 동작: 선택한 텍스트를 문체를 유지한 채 확장해 같은 위치에 치환합니다.
- 주의: 선택 영역이 비어 있으면 확장하지 않고 안내 메시지를 표시합니다.

## 5) 카드 기반 보충 / 지시문 편집 (재생성 없이)

- 공통: 초안을 **재생성하지 않고** 수정합니다. 적용 전 VSCode 네이티브 diff로 변경 전/후를 보여 주고, **적용**을 눌러야 반영됩니다. `storyboard.draft.keepHistory`가 켜져 있으면 적용 직전 초안을 `.draft` 히스토리에 보관합니다.

### 카드 기반 보충

- 명령: `Storyboard: Supplement Draft from Cards` / `Storyboard: Update Selection from Cards`
- 동작: 현재 캐릭터·배경 카드와 정전(canon) 설정을 기존 본문에 자연스럽게 녹여 보충합니다. 사건 전개·문체·사용자가 직접 고친 부분은 보존합니다.
  - **카드 기반 보충**: 본문 전체를 대상으로 보충합니다.
  - **선택 영역 보충**: 선택한 영역만 보충합니다(선택이 비어 있으면 안내 메시지).
- 카드를 갱신한 뒤 재생성으로 직접 편집분을 잃고 싶지 않을 때 사용합니다.

### 지시문 기반 편집

- 명령: `Storyboard: Edit Selection with Instruction...`
- 동작: 영역을 선택한 뒤 명령을 실행하고 입력 상자에 수정 방향(예: "더 긴장감 있게", "짧게 줄여서", "캐릭터 감정을 강조해서")을 적으면, 현재 카드·정전 정보와 함께 AI가 선택 영역을 재작성합니다. 같은 일을 Studio 대화로도 할 수 있습니다(씬 대상 대화에서 고칠 구간을 말로 지정).
  - 지시문이 없으면(취소 또는 빈 입력) 수정하지 않습니다.
  - 선택이 비어 있으면 안내 메시지를 표시합니다.

## 6) 초안 검수·재작성 루프

- 명령: `Storyboard: Review & Revise Draft (Current Scene)` — 기존 초안에 검수·재작성만 다시 돌리고 싶을 때 사용합니다.
- 자동 실행: `storyboard.draft.reviseAfterGenerate`가 기본 `true`라, 초안 생성(Generate / Regenerate / Generate All) 직후 이 루프가 자동으로 이어집니다. 한 동작으로 검수된 초안이 나오므로 위 명령을 따로 실행할 필요가 없습니다. 비용을 줄이려면 이 설정을 끕니다.
- 동작: 현재 초안을 연속성 검사와 비평(캐릭터 보이스, 장면 목적, 반복)으로 검수하고, 차단 이슈가 있으면 재작성합니다.
- 반복 횟수: `storyboard.draft.reviseMaxIterations` 설정을 따릅니다(기본 2, 최대 5).
- 점수 기준(선택): `storyboard.draft.reviseScoreThreshold`(0–100, 기본 0=비활성)을 설정하면, 비평 루브릭 점수가 기준 이상일 때 루프를 한 번 일찍 통과시킵니다. 기본값 0에서는 동작이 기존과 동일하며 AI 호출 수가 늘지 않습니다. 연속성 high 이슈는 점수와 무관하게 계속 차단합니다. 최종 검사 보고서에는 `비평 점수: NN/100` 줄이 함께 표시됩니다.
- 기록: 씬별 검수 시각, 재작성 횟수, 남은 차단 이슈, 재작성 지시를 `.storyboard/outline/revision-plan.yaml`에 누적합니다.
- 문체/품질 기준: `Storyboard: Open Settings`의 **작품 계약** 탭에 입력한 `styleConstraints`와 `qualityCriteria`가 비평 프롬프트에 반영됩니다.

## 7) 캐릭터 Hover 카드

- 대상: `draft/*.md` 본문에서 캐릭터 이름 위 Hover
- 표시 정보
  - 캐릭터 기본 요약
  - traits
  - recentDialogues
  - 관계 캐릭터 요약
- 데이터 소스: 워크스페이스 `character/*.card` 파일

## 8) 카드 에디터에서 draft 수집

- 대상: `character/*.card`, `background/*.card`를 커스텀 에디터로 열었을 때의 **수집** 탭
- 동작: **수집** 버튼을 누르면 이 카드가 등장하는 `draft/*.md`를 모아 LLM으로 카드에 추가할 정보를 추출합니다.
  - 캐릭터: 속성·관계·아크·특성·최근 대사·설명·화법·욕망
  - 배경: 설명·감각·시간·날씨·등장인물
- 검토: 제안은 git diff처럼 항목별 `+`(추가)/`-`→`+`(수정)으로 표시되며, 출처 씬도 함께 보여 줍니다.
- 신규 vs 수정: 관계는 target, 속성은 key, 시간/날씨, 아크는 sceneRef를 동일성 키로 봅니다. 같은 키가 없으면 추가, 있는데 값이 다르면 수정 제안으로 뜹니다. traits·설명·감각·대사 같은 자유 목록은 새 항목만 추가합니다.
- diff 미리보기: 체크박스로 항목을 고른 뒤 **diff 미리보기**를 누르면 VSCode 네이티브 diff 편집기가 현재 카드 YAML과 선택 반영본을 나란히 보여 줍니다.
- 반영: **선택 항목 반영**을 누르면 카드 YAML에 적용됩니다. 수정 항목은 사용자가 수락할 때만 기존 값을 덮어씁니다.

## 9) 캐릭터·배경 카드 추천

- 대상: 좌측 **Characters**/**Backgrounds** 뷰 헤더의 **추천**(✨) 버튼
- 동작: 프로젝트 전체 `scene/*.card`와 `draft/*.md`를 모아 LLM으로 읽고, 본문에 등장하지만 해당 탭에 아직 카드가 없는 인물·배경을 찾아 제안합니다.
  - 캐릭터: 이름·역할(main/supporting/extra) 추정·한 줄 설명
  - 배경: 이름·한 줄 설명
- 선택·생성: QuickPick에서 추가할 항목을 다중 선택하면 `character/*.card`·`background/*.card`로 생성됩니다. 이름·역할/종류·설명만 채운 최소 카드이며, 사이드바는 자동 갱신됩니다.
- 보강: 생성 후 세부 설정은 카드 에디터의 **수집** 탭(§7)으로 채웁니다.
- 이미 카드가 있는 이름과 별칭은 제안에서 제외됩니다.

## 10) 이야기 완결

- 실행: **`Storyboard: Complete Story Scenes`** 또는 Scenes 뷰 헤더.
- 읽기 범위: 유효한 모든 `scene/*.card`와 연속성 확인용 프로젝트 계약·canon·기존 카드입니다. `draft/`, outline, canon, 프로젝트 설정은 수정하지 않습니다.
- 검토: 모델은 씬 파일 경로가 아닌 slug와 메타데이터·본문만 제안합니다. 확장은 현재 최대 번호 다음에서 최대 20개까지 연속 번호를 코드가 붙입니다. QuickPick에서 첫 1개부터 전체까지 연속 prefix 하나를 고른 뒤 빈 문서와의 native diff를 확인합니다.
- 적용: 최종 **적용**을 눌러도 기존 씬은 수정하지 않고 새 씬만 만듭니다. 중심 질문·회수/열린 복선·클라이맥스 선택은 검토 정보이며 자동 차단 조건이 아닙니다.

## 11) 씬 기반 카드 구성

- 실행: **`Storyboard: Build Cards from Scenes`** 또는 Characters/Backgrounds 뷰 헤더.
- 근거: 유효한 `scene/*.card`만 새 사실의 근거입니다. 기존 카드는 이름·별칭 중복 판별과 기존 사실 보존을 위해서만 읽습니다. 씬은 4만 자 단위, 최대 4개 AI 호출로 병렬 처리합니다.
- 검토: 신규 캐릭터/장소와 기존 카드의 필드별 보강안이 한 QuickPick에 표시됩니다. 원하는 필드만 고르고 조립된 전체 YAML을 native diff로 확인합니다. 기존 사실 삭제는 제안하지 않습니다.
- 신규 카드: 배경은 v1에서 `location/place`만 만들며, 신규 캐릭터에는 `profile` 필드나 PNG를 만들지 않습니다. 비라틴 이름 또는 ID 충돌은 사용자가 고유 ID를 입력해야 합니다.
- 안전: 두 기능은 제안 당시의 소스·카드 SHA-256 스냅샷을 적용 직전에 다시 확인합니다. 달라졌으면 자동 병합하지 않고 **Regenerate**만 허용합니다. 선택 변경은 하나의 `WorkspaceEdit`로 적용하지만 크래시까지 보장하는 완전한 트랜잭션은 아닙니다.

## 12) 초안 헤더의 생성 경고

- 대상: `draft/*.md` 맨 위 frontmatter의 `warnings` 항목
- 언제 생기나: 씬 생성은 결과를 기계로 검증합니다. 뼈대에 없던 인물이 등장하거나, 다른 문자 체계가 섞이거나, 뼈대의 대사가 사라지거나, 분량이 목표의 절반에 못 미치면 사유를 붙여 최대 두 번 다시 만듭니다. 그래도 남는 위반이 있을 때만 이 항목이 붙습니다.

```yaml
---
sceneStem: 07-auction
warnings:
  - '2구간: 뼈대의 대사가 사라졌습니다 ("망치질이 평소와 달랐습니다")'
  - 대사 다듬기를 되돌렸습니다 — 외국 문자가 섞였습니다 ("তারপর")
---
```

- 읽는 법: 경고가 있어도 **원고는 그대로 나옵니다.** 결과를 버리지 않고 어느 대목을 먼저 봐야 하는지만 알려 주는 표시입니다.
  - `N구간: …` — 그 구간의 살붙임 결과에 남은 위반입니다. 해당 구간을 읽어 보고 필요하면 재생성하거나 선택 영역 편집(§5)으로 고칩니다.
  - `대사 다듬기를 되돌렸습니다 — …` — 대사를 손보는 단계가 사건을 늘리거나 문자를 오염시켜, 손보기 이전 상태를 채택했다는 뜻입니다. 사건은 안전하지만 인물별 말투 구분이 그 씬에서만 덜할 수 있습니다.
- 경고가 없으면 `warnings` 키 자체가 나오지 않습니다. 이 키가 없는 예전 초안도 그대로 읽힙니다.
- 경고를 지우려면 그 씬을 재생성합니다. 헤더를 손으로 지워도 검증 결과가 바뀌지는 않습니다.

## 13) 동작하지 않을 때 점검

1. 워크스페이스에 `.storyboard/project.json`이 있는지 확인
2. 파일이 `draft/*.md` 경로인지 확인
3. 기본 provider 및 task provider 설정(`Storyboard: Open Settings`) 확인
4. 원격 provider 사용 시 API 키 저장 여부 확인(`Storyboard: Set API Key...`)
5. 로컬 provider(Ollama) 사용 시 base URL/model 설정 확인
